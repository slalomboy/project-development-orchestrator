# Project Planning and Delivery Capability Map

[中文](../productization-map.md) · [Back to English README](../../README_EN.md)

| ID | Complete user outcome | Minimum input → output | Claimable handout | Paid upgrade |
|---|---|---|---|---|
| `FIN-PM-000` | Project control plane from ambiguity through verification, versioning, rollback, and review | Goal, current facts, constraints, and authority → project truth, plan, state, evidence, and delivery record | Intake-to-delivery process map | PD templates, cases, quality gates, and recovery system |
| `FIN-PM-001` | Executable brief and specification | Raw request, current situation, and constraints → six-field brief, acceptance, and open decisions | Six-field requirements card | PD traceability and change management |
| `FIN-PM-002` | Execution plan with dependencies and acceptance mapping | Approved scope/specification → stages, tasks, owners, dependencies, tests, and stop conditions | Task and acceptance mapping sheet | PD concurrency, ownership, progress, and portfolio management |
| `FIN-PM-003` | Layered acceptance report and gaps | Acceptance criteria, artifacts, and runtime evidence → six-surface conclusion and highest proven state | Six delivery-truth surfaces audit | PD automated checks, failure replay, and customer acceptance |
| `FIN-PM-004` | Traceable and recoverable version delivery record | Verified source/artifact, version policy, and authority → version, Tag/Release facts, compatibility, and rollback path | Version and delivery traceability checklist | PD update bundles, platform matrix, and rollback drills |

Each standalone outcome can be used by itself or composed through `FIN-PM-000`. Templates do not grant authority for deployment, publication, pushes, or permission changes.
